Détail des jobs

Deux jobs chaînés, définis dans .github/workflows/CI_CD_pipeline.yml.

lint-and-test (CI)

  • Déclenché à chaque push sur main / develop et à chaque PR vers main
  • Vérifie la présence du README.md
  • Analyse statique de tous les fichiers *.html avec HTMLHint
  • Fait échouer le pipeline à la moindre erreur

deploy-pages (CD)

  • Dépend du succès de la CI (needs: lint-and-test)
  • Exécuté uniquement lors d'un push sur main
  • Empaquette le site en artefact puis le déploie sur GitHub Pages
  • Expose l'URL publique via l'environnement github-pages

Bonnes pratiques mises en œuvre

Au-delà de l'automatisation, des choix pensés pour la fiabilité et la sécurité.

Workflow Git

Branche develop pour le travail courant, main pour la production. Intégration uniquement via Pull Request.

Moindre privilège

Permissions du GITHUB_TOKEN limitées au strict nécessaire : contents: read, pages: write, id-token: write.

Quality gate

Le déploiement est bloqué tant que la CI n'est pas au vert : aucun code invalide n'atteint la production.

Contrôle de concurrence

Le groupe concurrency: pages empêche deux déploiements simultanés d'entrer en conflit.
